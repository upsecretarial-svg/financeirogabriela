# PLANO DE IMPLEMENTAÇÃO: FILTRO POR MÊS PADRÃO (RECEBIMENTOS E CONTAS A PAGAR)

ESTE PLANO VISA CONFIGURAR O MÊS ATUAL COMO FILTRO PADRÃO NAS PÁGINAS DE RECEBIMENTOS E CONTAS A PAGAR, GARANTINDO ORGANIZAÇÃO E PREVENINDO A MISTURA DE DADOS DE DIFERENTES PERÍODOS.

## 1. CENTRAL DE RECEBIMENTOS (`src/routes/_authenticated/recebimentos.tsx`)
- **FILTRO PADRÃO**: AJUSTAR A INICIALIZAÇÃO DOS ESTADOS `from` E `to` PARA QUE SEMPRE COMECEM NO PRIMEIRO E ÚLTIMO DIA DO MÊS CORRENTE.
- **INTERFACE**: ADICIONAR UM SELETOR DE MÊS (`type="month"`) AO LADO DOS CAMPOS DE DATA PARA TROCA RÁPIDA DE PERÍODO.
- **LÓGICA**: ATUALIZAR OS FILTROS DE DATA AO MUDAR O MÊS NO SELETOR.

## 2. CONTAS A PAGAR (`src/routes/_authenticated/contas-pagar.tsx`)
- **ESTADO DE FILTRO**: ADICIONAR ESTADOS PARA `monthFilter` (ANO-MÊS) E INTERVALO DE DATAS (`from`, `to`).
- **INICIALIZAÇÃO**: DEFINIR O INTERVALO PADRÃO COMO O MÊS ATUAL.
- **QUERY DO SUPABASE**: MODIFICAR A QUERY `payables` PARA APLICAR OS FILTROS DE DATA `gte` E `lte` NA COLUNA `data_vencimento`.
- **INTERFACE**: INSERIR UM SELETOR DE MÊS NA BARRA DE FILTROS BENTO PARA NAVEGAÇÃO ENTRE MESES.

## DETALHES TÉCNICOS
- USO DE `new Date()` PARA CAPTURAR O PERÍODO VIGENTE EM TEMPO DE EXECUÇÃO.
- APLICAÇÃO DE FILTROS `gte` (MAIOR OU IGUAL) E `lte` (MENOR OU IGUAL) NAS QUERIES DO SUPABASE.
- GARANTIR QUE A MUDANÇA DE MÊS DISPARE O REFETCH DOS DADOS VIA TANSTACK QUERY.
